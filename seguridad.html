AWS Security & Marcos de Seguridad

Ejemplos Prácticos, Relaciones y Test CLF-C02

Caso Real Integrado: Banco Digital en AWS

Así es como trabajan en equipo todos estos marcos y servicios dentro de una misma arquitectura de producción:

Paso 1 · Estrategia (Antes de construir)
AWS CAF (Cloud Adoption Framework)
La directiva del banco usa la perspectiva de Seguridad del CAF para definir políticas de cumplimiento bancario, roles del equipo y controles obligatorios antes de migrar un solo servidor.
Paso 2 · Perímetro (Entrada de usuarios)
AWS Shield + AWS WAF
Cuando los clientes entran a la app web, Shield absorbe ataques masivos de red (DDoS) y WAF filtra intentos de inyección SQL o bots maliciosos antes de que lleguen al Application Load Balancer.
Paso 3 · Prevención interna (Servidores y Código)
Amazon Inspector
Mientras la app funciona, Inspector escanea continuamente las instancias EC2 y contenedores ECR. Avisa si una librería de Linux tiene un fallo crítico (CVE) para parcharla antes de que sea explotada.
Paso 4 · Detección activa (Comportamiento anómalo)
Amazon GuardDuty
Si un atacante logra robar una credencial y empieza a consultar datos desde un país extraño a las 3:00 AM, GuardDuty detecta la anomalía analizando logs de CloudTrail y VPC Flow Logs y dispara una alerta.
Paso 5 · Protección de Datos Sensibles
Amazon Macie + AWS KMS
Los estados de cuenta en PDF se guardan cifrados con claves de KMS en Amazon S3. Macie escanea los buckets para asegurar que nadie subió un archivo con números de tarjeta sin protección o en un bucket público.
Paso 6 · Centro de Mando Unificado
AWS Security Hub
El equipo de seguridad no entra a 5 consolas distintas: Security Hub recoge las alertas de GuardDuty, Inspector y Macie en un solo panel y mide si cumplen con normativas internacionales (PCI-DSS, CIS).

Comparativa Rápida para No Confundirlos

AWS CAF vs. AWS Well-Architected Framework:
El CAF guía a la organización y personas para adoptar la nube. El Well-Architected evalúa la arquitectura técnica de una carga de trabajo ya construida.
Amazon Inspector vs. Amazon GuardDuty:
Inspector busca debilidades conocidas (software desactualizado, puertos abiertos) antes del ataque. GuardDuty detecta comportamientos maliciosos activos (intrusiones, minería de criptomonedas) analizando tráfico y logs.
AWS WAF vs. AWS Shield:
WAF inspecciona el contenido de peticiones web (Capa 7: SQLi, XSS, bloqueo por país). Shield protege contra inundaciones de tráfico volumétrico (Capas 3/4 y 7: ataques DDoS).
AWS CloudTrail vs. AWS Config:
CloudTrail registra quién hizo qué acción (llamadas a la API). Config registra cómo cambió la configuración de un recurso a lo largo del tiempo.
