🛡️ AWS IAM (CLF-C02)

Conceptos IAM

¿Qué es AWS IAM?

  • Identity and Access Management: Servicio global y fundamental de AWS.
  • Controla de forma segura quién (autenticación) y qué (autorización) puede acceder a los recursos.
  • Opera de manera global en toda la infraestructura de la nube de AWS.
👑 Usuario Raíz (Root): El dueño absoluto de la cuenta. Nunca debe usarse para tareas diarias y requiere MFA.
Identidades

Usuarios y Grupos IAM

  • Usuarios IAM: Credenciales individuales para personas físicas o aplicaciones.
  • Grupos IAM: Colección de usuarios que comparten permisos por departamentos (ej. Finanzas o Desarrollo).
  • Los grupos facilitan la administración masiva de accesos.
👥 Nota clave: Un grupo IAM no puede contener otros grupos dentro de él.
Permisos Avanzados

Roles y Políticas JSON

  • Roles IAM: Identidades temporales que se "prestan" a servicios o usuarios externos sin llaves fijas.
  • Políticas JSON: Reglas estructuradas que determinan los permisos exactos.
  • Componentes clave: Effect (Allow/Deny), Action y Resource.
🛡️ Regla de oro: Un Deny explícito tiene precedencia absoluta sobre cualquier Allow.
Seguridad Clave

Mejores Prácticas Obligatorias

  • Mínimo Privilegio: Otorgar únicamente los permisos estrictamente necesarios para operar.
  • MFA (Autenticación Multifactor): Añadir una capa extra de verificación física/digital.
  • Rotación de Credenciales: Evitar claves estáticas incrustadas en código fuente.
🔑 Objetivo CLF-C02: Minimizar la superficie de ataque en entornos corporativos.
Caso Real 1

Instancia EC2 leyendo S3 mediante Rol

  • 1. Se crea un Rol IAM con permisos de solo lectura para Amazon S3.
  • 2. Se define una relación de confianza exclusiva para el servicio EC2.
  • 3. Se asigna el rol directamente al lanzar la máquina virtual EC2.
  • 4. La aplicación obtiene credenciales temporales automáticas sin contraseñas en código.
🚀 Ventaja: Cero credenciales estáticas expuestas en archivos de configuración.
Caso Real 2

Auditoría Externa y Raíz

  • Acceso Temporal: Se asigna un Rol IAM con expiración automática (ej. 2 horas) a auditores externos.
  • Protección Raíz: Se bloquea el acceso físico diario del usuario raíz tras configurar credenciales MFA.
🔑 Resultado: Cumplimiento normativo y seguridad estricta sin accesos huérfanos.
